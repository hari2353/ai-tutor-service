## The 30-second version

Q-learning and SARSA are both TD control algorithms — they learn `Q(s,a)` online from single transitions — and differ in exactly one line of code with a large behavioral consequence: SARSA's target uses the action the agent *actually takes next*, `r + \gamma Q(s',a')` with `a' \sim \pi(\cdot|s')`, making it **on-policy** — it evaluates and improves the same policy that generates its data, exploration mistakes and all. Q-learning's target uses `r + \gamma \max_{a'} Q(s',a')`, the best action available from `s'` regardless of what the agent will actually do next, making it **off-policy** — it learns the value of the *greedy* policy while behaving according to a different, exploratory one. The textbook demonstration is cliff walking: Q-learning learns the value of walking right along the cliff edge (optimal if you never slip) and keeps executing that risky path during training, occasionally falling off when its ε-greedy exploration slips; SARSA learns the value of the path *including* the chance of an exploratory slip, and converges to a safer route further from the edge. Neither is "more correct" — they're answering different questions ("what's optimal" vs "what's optimal given I'll keep exploring like this"), and the choice has real production consequences whenever exploration itself carries risk.

## Why this gets asked

Because it's the highest-yield RL interview question after the Bellman equation: candidates who've only read about Q-learning give a definition; candidates who've implemented both can explain *why* the cliff-walking curves look different, which requires actually understanding what "off-policy" means operationally, not just as a vocabulary word. Interviewers who've deployed RL where exploration is expensive or dangerous (robotics, any system touching real users or money) have specifically hit the "Q-learning behaves more aggressively than you want during training" failure and want to know you'd predict it before it happens, not diagnose it after an incident.

## Lineage: past → present → future

**What came before.** Before Watkins' Q-learning (1989), TD prediction (`T31-monte-carlo-td`) only estimated the value of a *given* policy — useful for evaluation but not directly for finding a better one, without an explicit outer policy-improvement loop like DP's. Watkins' contribution was proving that a single, simple TD-style update — bootstrap toward the max over next-state actions — converges directly to `Q^*`, the optimal action-value function, *without* needing an explicit alternating improve-then-evaluate loop and, crucially, without needing the *behavior* policy generating the data to be optimal or even good, only sufficiently exploratory. SARSA (Rummery & Niranjan, 1994, later named by Sutton) filled the on-policy gap: sometimes you specifically want to evaluate and improve the policy you're actually running, warts and all — because during learning, that *is* the policy incurring real-world consequences.

**Where it stands now.** Both are foundational and completely settled as tabular algorithms; the live question is entirely about which property (off-policy vs on-policy) you want when scaling up. Off-policy learning is what makes experience replay possible (DQN, `T31-dqn`) — you can reuse old transitions generated by an old, different policy because Q-learning's update doesn't require the data to come from the current policy, only that it covers the relevant state-action pairs. On-policy learning underlies most modern policy-gradient and actor-critic methods (`T31-policy-gradient`, `T31-ppo`), where the object being learned (a stochastic policy) inherently needs data generated by roughly that policy to have a valid gradient estimate — PPO's whole clipping mechanism exists specifically to police how far the data-generating policy has drifted from the policy being updated, a distinctly on-policy concern. Expected SARSA (weight over the full next-action distribution instead of sampling or maxing) is a well-known middle variant that reduces SARSA's variance while staying formally on-policy, used less often than either pure extreme but worth knowing exists.

**Where it's heading.** High confidence: the off-policy/on-policy distinction stays a first-class design axis in every RL system, because it maps directly onto the practical question "can I reuse old data" (a huge sample-efficiency and infrastructure question at scale). Medium confidence: off-policy methods keep gaining ground in domains with expensive data collection (robotics, large-scale RLHF variants) specifically because they permit replay and offline reuse (`T31-offline-rl`), while on-policy methods remain preferred wherever training stability and predictable, current-policy behavior during learning matter more than sample efficiency. Speculative: some 2025-2026 work explores hybrid off-policy corrections that let nominally on-policy algorithms (PPO-family) tolerate more off-policy-ness for better sample reuse without the stability loss classically associated with mixing bootstrapping, off-policy data, and function approximation (the deadly triad, `T31-rl-framing`) — treat claims that this is fully solved as premature.

## Mental model

```
                 SARSA (on-policy)                    Q-LEARNING (off-policy)

  s -a-> r, s' -a'(actually taken)-> ...     s -a-> r, s' -(a' = best possible, MAX)-> ...

  target = r + γ Q(s', a')                   target = r + γ max_a' Q(s', a')
           where a' ~ π(·|s')  (ε-greedy)              regardless of what's taken next

  "How good is the plan I'm ACTUALLY          "How good is the plan I COULD follow
   going to follow, mistakes and all?"          if I always played optimally from here?"
```

SARSA asks a question about *your actual future behavior*, including the chance you'll trip over your own exploration. Q-learning asks a question about *the best possible future*, as if exploration noise didn't exist past this one step. Both are legitimate questions — they just answer different ones, and cliff walking is the environment engineered to make the difference between the answers impossible to miss.

## How it actually works

### SARSA, derived from the Bellman expectation equation for Q

Recall from `T31-mdp`: `Q^\pi(s,a) = \sum_{s'}P(s'|s,a)[R(s,a,s')+\gamma\sum_{a'}\pi(a'|s')Q^\pi(s',a')]`. SARSA is the direct TD-style sample-based version of this equation — instead of computing the exact expectation over `s'` and `a'`, it uses one sampled `(s,a,r,s',a')` quintuple (hence the name: **S**tate, **A**ction, **R**eward, **S**tate, **A**ction):

$$Q(s,a) \leftarrow Q(s,a) + \alpha\left[r + \gamma Q(s',a') - Q(s,a)\right], \qquad a' \sim \pi(\cdot|s')$$

Because `a'` is sampled from the *actual behavior policy* `π` (typically ε-greedy w.r.t. the current `Q`), this update is a genuine sample of the Bellman expectation equation for `Q^π` under exactly the policy generating the data — SARSA is on-policy by construction, not by convention: the target quantity it's estimating (`Q^π`) is defined in terms of the same `π` that chose `a'`.

### Q-learning, derived from the Bellman optimality equation for Q

Recall from `T31-mdp`: `Q^*(s,a) = \sum_{s'}P(s'|s,a)[R(s,a,s')+\gamma\max_{a'}Q^*(s',a')]`. Q-learning is the TD-style sampled version of *this* equation instead:

$$Q(s,a) \leftarrow Q(s,a) + \alpha\left[r + \gamma\max_{a'}Q(s',a') - Q(s,a)\right]$$

The `max_{a'}` doesn't require sampling `a'` from anything — it's computed directly from the current `Q` table, independent of what action the agent's behavior policy would actually choose next. This is precisely why Q-learning is off-policy: the *target policy* being evaluated (implicitly, the greedy policy w.r.t. `Q`) is different from the *behavior policy* actually selecting actions and generating the `(s,a,r,s')` data (typically ε-greedy, which must still explore for the state-action coverage Q-learning's convergence proof requires). Watkins & Dayan (1992) proved Q-learning converges to `Q^*` with probability 1 under standard stochastic-approximation step-size conditions, provided every `(s,a)` pair is visited infinitely often — a real, checkable requirement, not a technicality, since a state-action pair that's never explored can never have its `Q`-value corrected.

### The formal off-policy/on-policy distinction

**On-policy**: the policy used to generate behavior (choose actions) and the policy being evaluated/improved are the same. SARSA's target uses `Q(s',a')` for the `a'` the *behavior* policy actually would pick — evaluating exactly the policy generating the data.

**Off-policy**: the behavior policy (generating data) and the target policy (being learned about) differ. Q-learning's target uses `\max_{a'}Q(s',a')` — the value under the *greedy* target policy — while actions are actually chosen by a different, exploratory behavior policy. This is also why off-policy methods generically need some form of correction (importance sampling in general off-policy prediction) when the two policies diverge significantly — Q-learning specifically sidesteps needing explicit importance sampling because the `max` operator already defines exactly what the target policy is (the greedy one), rather than needing to reweight samples from an arbitrary, separately-specified target policy.

### Cliff walking, worked precisely

Standard setup: a 4×12 grid, start bottom-left, goal bottom-right, a "cliff" occupying the bottom row between them. Stepping onto the cliff gives reward `-100` and resets to start; every other step gives `-1`. Both algorithms train with ε-greedy behavior (small ε, e.g. 0.1).

**What Q-learning learns.** Its target always uses `\max_{a'}Q(s',a')` — the value of the *best* action from the next state, ignoring that the actual next action might be an ε-exploration step. Along the cliff-edge path, the greedy continuation is short and fast (reward-optimal *if followed exactly*), so `Q` converges to favor the cliff-edge route — the genuinely optimal deterministic policy. But the agent's actual *behavior* during training is still ε-greedy, so roughly ε fraction of steps along that edge are random, and a random step off the cliff edge costs `-100` and a reset. The learned policy is optimal; the *training-time behavior* running it is not, because Q-learning evaluates a policy it isn't actually following.

**What SARSA learns.** Its target uses `Q(s',a')` for the `a'` actually sampled from the ε-greedy behavior policy — so the value of being near the cliff edge *already reflects* the ε chance of a random step off it. That expected cost pulls `Q` for cliff-adjacent states down relative to a safer route, so SARSA converges to a path that stays further from the edge — a longer path with a lower `-1`-per-step total, but far lower risk of the `-100` penalty, because it's evaluating the policy it will *actually run*, exploration included.

**The numbers this produces (canonical result, Sutton & Barto).** Averaged over training, SARSA achieves a *higher average per-episode reward during training* than Q-learning, because Q-learning's training-time behavior keeps walking near the cliff and eating occasional `-100` penalties even as its `Q`-table correctly converges toward the optimal (cliff-edge) policy. After training, if you *stop* exploring (set ε=0) and roll out each learned greedy policy, Q-learning's is shorter and achieves higher return — because it did learn the genuinely optimal deterministic policy, it just wasn't safe to run *during* the exploratory training process itself.

## Build it from scratch

Both algorithms, tabular, on the cliff-walking environment, logging the exact quantity that makes the difference visible: reward accumulated *during training* (with exploration still active), not just the final policy's quality.

```python
import numpy as np

class CliffWalking:
    """4x12 grid. Start (3,0), goal (3,11). Row 3, cols 1-10 is the cliff.
    Actions: 0=up 1=right 2=down 3=left."""
    def __init__(self):
        self.rows, self.cols = 4, 12
        self.start, self.goal = (3, 0), (3, 11)
        self.cliff = {(3, c) for c in range(1, 11)}
        self.deltas = {0: (-1, 0), 1: (0, 1), 2: (1, 0), 3: (0, -1)}

    def reset(self):
        self.pos = self.start
        return self.pos

    def step(self, a):
        r, c = self.pos
        dr, dc = self.deltas[a]
        r2, c2 = min(max(r + dr, 0), self.rows - 1), min(max(c + dc, 0), self.cols - 1)
        s2 = (r2, c2)
        if s2 in self.cliff:
            return self.start, -100.0, False   # fall off: -100, reset to start, episode continues
        self.pos = s2
        done = s2 == self.goal
        return s2, -1.0, done

def eps_greedy(Q, s, eps, n_actions=4):
    if np.random.rand() < eps:
        return np.random.randint(n_actions)
    return int(np.argmax(Q[s]))

def sarsa(env, n_episodes=500, alpha=0.5, gamma=1.0, eps=0.1):
    Q = {(r, c): np.zeros(4) for r in range(env.rows) for c in range(env.cols)}
    episode_returns = []
    for ep in range(n_episodes):
        s = env.reset()
        a = eps_greedy(Q, s, eps)
        total_r, done = 0.0, False
        while not done:
            s2, r, done = env.step(a)
            a2 = eps_greedy(Q, s2, eps)          # SARSA: sample the NEXT action first
            target = r + gamma * Q[s2][a2]        # target uses the action ACTUALLY taken
            Q[s][a] += alpha * (target - Q[s][a])
            s, a = s2, a2
            total_r += r
        episode_returns.append(total_r)
    return Q, episode_returns

def q_learning(env, n_episodes=500, alpha=0.5, gamma=1.0, eps=0.1):
    Q = {(r, c): np.zeros(4) for r in range(env.rows) for c in range(env.cols)}
    episode_returns = []
    for ep in range(n_episodes):
        s = env.reset()
        total_r, done = 0.0, False
        while not done:
            a = eps_greedy(Q, s, eps)
            s2, r, done = env.step(a)
            target = r + gamma * np.max(Q[s2])    # Q-learning: target uses the BEST possible action
            Q[s][a] += alpha * (target - Q[s][a])
            s = s2
            total_r += r
        episode_returns.append(total_r)
    return Q, episode_returns

if __name__ == "__main__":
    np.random.seed(0)
    Q_sarsa, ret_sarsa = sarsa(CliffWalking())
    np.random.seed(0)
    Q_qlearn, ret_qlearn = q_learning(CliffWalking())

    # average reward over the LAST 100 training episodes, exploration still active (eps=0.1)
    print(f"SARSA      avg training return (last 100 ep): {np.mean(ret_sarsa[-100:]):.1f}")
    print(f"Q-learning avg training return (last 100 ep): {np.mean(ret_qlearn[-100:]):.1f}")
    # Expect: SARSA's training-time average is HIGHER (safer route, fewer -100 falls)
    # even though Q-learning's Q-table has converged toward the shorter, riskier optimal path.
```

Run this and compare `ret_sarsa[-100:]` against `ret_qlearn[-100:]`: SARSA's training-time average should sit noticeably higher than Q-learning's, reproducing the canonical result — not because SARSA "learned better," but because it learned the value of the policy it was actually running, exploration risk included, while Q-learning kept walking the cliff edge during training even as its table converged to the objectively shorter optimal path.

## How it's done in production

| Layer | What you actually use | What it adds |
|---|---|---|
| Tabular control | SARSA / Q-learning directly, small discrete problems | Rarely deployed unmodified at scale; foundational for everything below |
| Deep off-policy value learning | DQN and variants (`T31-dqn`) — Q-learning's update with a neural net `Q_θ` and a replay buffer | Off-policy-ness is *why* replay buffers work: old transitions from an old policy are still valid training data for Q-learning's target, which doesn't require the data-generating policy to match the target policy |
| Deep on-policy control | Expected SARSA, or (more commonly at scale) on-policy policy-gradient/actor-critic methods (`T31-policy-gradient`, `T31-ppo`) | On-policy-ness enforces that training data reflects the current policy's actual behavior, which PPO's clipped objective specifically manages as the policy updates |
| Safety-sensitive training | On-policy methods (SARSA-family or on-policy actor-critic) preferred when the *training-time* trajectory itself has real-world cost | The training-time behavior is part of what's being optimized, not just the eventual converged policy |

### Failure modes

| Symptom | Cause | Fix |
|---|---|---|
| Q-learning agent behaves riskier during training than a stakeholder expects, even though eval-time (ε=0) performance is great | Off-policy learning: Q-learning optimizes the greedy target policy's value, not the actual ε-greedy training behavior's safety | If training-time behavior matters (real robot, real users), use SARSA or reduce ε over training (GLIE schedules), not Q-learning as-is |
| Q-learning table never converges for some state-action pairs | Those pairs are never visited under the exploration policy — violates the "infinite visitation" requirement of Watkins' convergence proof | Verify exploration actually covers the relevant state-action space; increase ε or use a more systematic exploration strategy (`T31-exploration`) |
| SARSA and Q-learning give visibly different learned policies and someone assumes one is "wrong" | Expected, not a bug — they're solving genuinely different objectives (safe-given-exploration vs objectively-optimal) | Confirm intentionally: articulate which objective the deployed system actually needs before picking either |
| Mixing SARSA's on-policy update with a replay buffer produces poor or unstable learning | Replayed transitions come from an old policy's `a'`, but SARSA's target formula assumes `a'` reflects the *current* policy — an invalid on-policy assumption under stale data | Don't naively replay for on-policy algorithms; either discard replay for SARSA-style updates or switch to an off-policy formulation (Q-learning / Expected SARSA with importance correction) if replay is required |

## Tradeoffs & when NOT to use it

- **Use Q-learning (or an off-policy method generally) when you want to reuse old data or when training-time exploratory risk is acceptable and only the final policy's quality matters.** Its off-policy property is exactly what unlocks experience replay and offline reuse downstream.
- **Use SARSA (or an on-policy method generally) when the process of learning itself has real consequences** — a physical robot, a system interacting with real users during training — because it optimizes for the policy actually being executed, exploration mistakes included, rather than an idealized greedy policy you aren't actually running yet.
- **Don't assume either algorithm's tabular convergence guarantee survives function approximation unchanged.** Both are provably convergent in the tabular case under standard conditions; Q-learning specifically inherits deadly-triad risk once combined with function approximation and off-policy replay (`T31-dqn`'s entire target-network story exists because of this).
- **Don't pick between them based on which is "newer" or "more popular."** Q-learning is the more famous name and the basis for DQN, but that doesn't make it the right choice whenever on-policy safety-during-training is the actual requirement — this is a substance decision, not a trend decision.
- **Expected SARSA is worth knowing as the reasonable middle ground**: it replaces SARSA's sampled `a'` with the full expectation `\sum_{a'}\pi(a'|s')Q(s',a')`, staying strictly on-policy while removing the extra sampling variance SARSA pays for using just one sampled `a'` — a real, usable option when SARSA's variance (not its fundamental on-policy-ness) is the actual pain point.

## Interview questions

### Q1 — State the update rule for both SARSA and Q-learning, and identify the exact single difference.
**Answer:** SARSA: `Q(s,a) \leftarrow Q(s,a)+\alpha[r+\gamma Q(s',a')-Q(s,a)]` where `a'` is the action actually sampled from the behavior policy at `s'`. Q-learning: `Q(s,a)\leftarrow Q(s,a)+\alpha[r+\gamma\max_{a'}Q(s',a')-Q(s,a)]`. The only difference is whether the next-state term is `Q(s',a')` for the sampled `a'` (SARSA) or `\max_{a'}Q(s',a')` (Q-learning) — but that one substitution is the entire on-policy/off-policy distinction.
**Follow-up trap:** *"If the behavior policy is fully greedy (ε=0), are SARSA and Q-learning identical?"* — yes, exactly: with ε=0, the action actually sampled *is* the greedy action, so `Q(s',a')=\max_{a'}Q(s',a')` and the two updates coincide. The distinction only matters because behavior policies must explore (ε>0) for convergence, and that's precisely where the two updates diverge.

### Q2 — Define on-policy and off-policy precisely, using SARSA and Q-learning as the examples.
**Answer:** On-policy: the behavior policy (generates the data) and the target policy (being learned/evaluated) are the same policy. SARSA is on-policy because its target explicitly uses the action the behavior policy would actually take, so it's evaluating exactly that policy. Off-policy: behavior and target policies differ. Q-learning is off-policy because its target uses the max — implicitly evaluating the greedy target policy — while actions are actually generated by a separate, exploratory behavior policy.
**Follow-up trap:** *"Is 'on-policy' the same as 'no exploration'?"* — no, a common confusion: SARSA explores too (typically ε-greedy) and is still on-policy, because it evaluates *that same ε-greedy policy*, exploration included, rather than a different, better one. On-policy is about whether behavior and target policy match, not about whether exploration happens.

### Q3 — Walk through why Q-learning and SARSA produce different learned paths on cliff walking. Be specific about the mechanism, not just the outcome.
**Answer:** Q-learning's target always uses `\max_{a'}Q(s',a')`, the value of the best next action, so a state near the cliff edge gets its `Q`-value computed as if the agent would always act optimally from there onward — ignoring that its actual ε-greedy behavior has a real chance of a random step off the cliff. That makes cliff-adjacent states look good in `Q`, so the greedy policy derived from `Q` hugs the edge. SARSA's target uses `Q(s',a')` for the action the ε-greedy policy actually samples next, so the value of a cliff-adjacent state already has the ε-probability of an accidental fall (and its `-100` cost) baked in, pulling that state's value down and pushing the learned policy toward a safer route.
**Follow-up trap:** *"If you set ε to decay to 0 over training for both algorithms, does the gap eventually disappear?"* — largely yes: as ε→0, the behavior policy approaches greedy, at which point (per Q1's follow-up) SARSA's update converges toward Q-learning's, and both should converge toward the same optimal deterministic policy — the training-time behavioral difference specifically depends on maintained, nonzero exploration.

### Q4 — Which algorithm achieves higher *average reward during training* on cliff walking, and why doesn't that mean it's "better"?
**Answer:** SARSA achieves higher average reward during training, because it avoids the cliff more often while still exploring — its policy is safety-aware given ongoing exploration. It doesn't mean SARSA is "better" in general: Q-learning's `Q`-table converges to the objectively optimal deterministic policy (shorter path, higher return once exploration is turned off), it just isn't safe to *run* during the exploratory training process itself. Which one is "better" depends entirely on whether training-time behavior has real consequences.
**Follow-up trap:** *"So is SARSA always the safer choice for real-world training?"* — it's the *more predictable* choice for real-world training-time behavior specifically, but "safer" still depends on ε and the actual risk structure of your problem; SARSA with a large ε can still be risky, and Q-learning with sufficiently small, carefully scheduled exploration (or exploration restricted to provably safe actions) can be made acceptable too — the algorithm choice doesn't substitute for actually reasoning about the exploration policy's real-world risk.

### Q5 — Why does Q-learning's off-policy property make experience replay valid, while naively replaying for vanilla SARSA is a problem?
**Answer:** Q-learning's target, `r+\gamma\max_{a'}Q(s',a')`, doesn't reference the behavior policy that generated the transition at all — it only needs `(s,a,r,s')`, and computes the target policy's (greedy) value directly from the current `Q` table regardless of which policy originally chose `a` or would choose `a'`. So a transition collected under an old policy is still a valid training example for today's target. SARSA's target explicitly needs `a'`, the action the *current* behavior policy would take at `s'` — a stored, replayed transition has a stale `a'` recorded under a possibly very different old policy, so directly reusing it violates the on-policy assumption the update relies on.
**Follow-up trap:** *"Could you fix SARSA to work with a replay buffer?"* — yes, with modification: Expected SARSA replaces the sampled `a'` with an expectation `\sum_{a'}\pi_{\text{current}}(a'|s')Q(s',a')` computed fresh under the *current* policy at replay time (not the stale recorded action), which restores validity — but that's no longer literally using the replayed action, it's using the replayed `(s,a,r,s')` with a freshly recomputed target, a real design change, not free reuse.

### Q6 — What convergence guarantee does Q-learning have, and what's the one condition that's easy to accidentally violate in practice?
**Answer:** Watkins & Dayan (1992) proved Q-learning converges to `Q^*` with probability 1 under standard stochastic approximation step-size conditions (`\sum\alpha_t=\infty`, `\sum\alpha_t^2<\infty`), provided every state-action pair is visited infinitely often. The easy-to-violate condition in practice is that last one: if your exploration policy systematically avoids some region of the state-action space (too little exploration, a poorly designed ε-schedule, or an environment where some states are simply hard to reach under any reasonable behavior policy), those `Q`-values never get corrected and can be arbitrarily wrong despite everything else in the algorithm being implemented correctly.
**Follow-up trap:** *"Your Q-table has converged (stopped changing) for the states you've observed, but performance is still bad on rare edge cases. Does that contradict the convergence proof?"* — no: convergence to `Q^*` requires infinite visitation of *every* `(s,a)`; if rare edge-case states are visited rarely (not infinitely often, in the limit of training), the proof simply doesn't apply to them — a converged-looking table can still have arbitrarily poor values on states your exploration policy under-visited, which is a coverage problem, not a violation of the convergence theorem.

### Q7 — Explain Expected SARSA and why it's still on-policy despite removing the sampling of `a'`.
**Answer:** Expected SARSA's target is `r+\gamma\sum_{a'}\pi(a'|s')Q(s',a')` — the exact expectation over the behavior policy's action distribution at `s'`, rather than one sampled `a'`. It's still on-policy because the *policy being evaluated in the target* (`π`, the behavior policy) is identical to the policy actually generating the data — the only change from vanilla SARSA is replacing a one-sample Monte Carlo estimate of that expectation with the exact expectation, which reduces variance without changing which policy is being evaluated.
**Follow-up trap:** *"If you replace π in the expectation with the greedy policy instead of the actual behavior policy, what do you get?"* — exactly Q-learning: `\sum_{a'}\pi_{\text{greedy}}(a'|s')Q(s',a')` collapses to `\max_{a'}Q(s',a')` since the greedy policy puts all probability on the argmax — which is a clean, direct way to see that Q-learning is literally the off-policy special case of Expected SARSA where the target policy is fixed to greedy regardless of what the behavior policy actually is.

### Q8 — Design the training setup for a real warehouse robot learning to navigate near a genuinely hazardous zone (not a game). Which algorithm, and what else do you change?
**Testing:** applying the theory to a real risk-bearing production scenario.
**Answer:** SARSA (or Expected SARSA for lower variance), specifically because training-time behavior has real physical consequences and Q-learning's off-policy target would keep the robot executing risky near-hazard trajectories during the entire exploration phase even as its table converges toward an objectively shorter path. Beyond the algorithm choice: use a conservative, possibly hand-constrained action set near the hazard (physically prevent certain actions rather than relying purely on learned value to avoid them), decay ε over training (a GLIE schedule) so exploratory risk shrinks as the policy improves, and consider training substantially in simulation first (`T31-rl-in-production`) so the riskiest phase of learning never touches the real hazard at all.
**Follow-up trap:** *"Your simulator doesn't perfectly model the hazard zone's physics. Does SARSA's safety property still hold once you deploy the sim-trained policy?"* — no, and this is a real gap: SARSA's training-time safety argument is about the policy actually being executed *during training*, which in a sim-to-real pipeline is the simulated robot, not the real one; the real robot's first real-world exposure is deployment, not training, so sim-to-real gap (`T31-rl-in-production`) becomes the dominant risk regardless of which tabular control algorithm was used inside the simulator.

### Q9 — A candidate says "Q-learning is strictly better than SARSA because it learns the optimal policy." How do you respond?
**Testing:** whether the candidate can push back on a plausible-sounding but incomplete claim.
**Answer:** It's true that Q-learning's converged `Q`-table represents the optimal *deterministic* policy's values, but "learns the optimal policy" conflates the eventual converged answer with the training-time process that gets you there — and the training-time behavior, which still executes real actions with real consequences in any physical or user-facing system, is worse (riskier) under Q-learning specifically because it doesn't account for its own exploration. "Better" depends on whether you're optimizing for eventual policy quality alone or also for the safety/cost of the learning process itself; SARSA is the correct choice under the latter objective, and dismissing it as strictly worse ignores that entire dimension.
**Follow-up trap:** *"Does this argument change once ε is decayed to a very small value late in training?"* — yes, partially: as ε→0 the two algorithms' targets converge to each other (Q1's follow-up), so the practical behavioral gap shrinks over the course of training with a good ε-schedule — but early-to-mid training, where ε is still meaningfully large, is exactly when the difference matters most, and that's not a phase you can skip.

### Q10 — Both algorithms are tabular here. What specifically breaks, or needs modification, when you move to function approximation (a neural net `Q_θ`) for each?
**Answer:** Q-learning combined with function approximation and (usually) a replay buffer assembles all three legs of the deadly triad (function approximation + bootstrapping + off-policy data, `T31-rl-framing`) — no convergence guarantee, and DQN's entire target-network and replay-buffer design (`T31-dqn`) exists specifically to mitigate the resulting instability. SARSA with function approximation avoids the off-policy leg (it's still evaluating the policy generating the data), which in principle makes it structurally safer from the deadly triad, but on-policy learning with function approximation is far less sample-efficient in practice because you can't reuse a replay buffer the same way, and on-policy deep RL therefore usually takes a different algorithmic path entirely (policy-gradient/actor-critic, `T31-policy-gradient`) rather than "SARSA with a neural net," which is much less common in practice than "Q-learning with a neural net" (i.e. DQN).
**Follow-up trap:** *"Why is 'deep SARSA' so much rarer in practice than DQN, if it's structurally safer from the deadly triad?"* — because on-policy learning's inability to reuse a large, diverse replay buffer is a severe practical sample-efficiency cost in deep RL, where environment interaction is expensive; the field largely decided that off-policy methods with careful stabilization (target networks, clipped double Q-learning) or dedicated on-policy policy-gradient methods (which sidestep the issue differently, via fresh rollouts each update) are more practical paths than deep SARSA specifically.

## Red flags that fail you

- Confusing "on-policy" with "no exploration," or claiming SARSA doesn't explore.
- Not being able to state the exact one-term difference between the two update rules from memory.
- Claiming Q-learning is "just better" without acknowledging the training-time behavioral cost.
- Believing SARSA and Q-learning would produce identical results on cliff walking.
- Not knowing why Q-learning's off-policy property is what enables experience replay.
- Missing the "infinite visitation" requirement when asked about Q-learning's convergence guarantee.
- Assuming tabular convergence guarantees survive function approximation unchanged.

## Cheat card

```
SARSA          Q(s,a) += alpha*[r + gamma*Q(s',a') - Q(s,a)]   a' = ACTUALLY sampled next action
               ON-POLICY: target policy = behavior policy (same pi being followed and evaluated)
Q-LEARNING     Q(s,a) += alpha*[r + gamma*max_a' Q(s',a') - Q(s,a)]
               OFF-POLICY: target = greedy policy's value; behavior = separate exploratory policy
IDENTICAL AT   eps=0 (fully greedy behavior): sampled a' = argmax => SARSA == Q-learning exactly
CLIFF WALKING  Q-learning -> learns/executes cliff-edge (shortest, riskiest) path during training
               SARSA -> learns/executes safer path away from edge (values include eps-fall risk)
               SARSA has HIGHER avg reward DURING training; Q-learning's final greedy policy
               (eps=0 rollout) is shorter/better once exploration stops
WHY REPLAY OK  Q-learning target uses only (s,a,r,s'), no dependency on behavior policy's a'
               -> old transitions from old policies remain valid training data
WHY SARSA+     replayed a' is STALE (from an old policy) -> violates on-policy target assumption;
REPLAY BREAKS  fix = Expected SARSA recomputing E_{a'~pi_current}[Q(s',a')] fresh at replay time
EXPECTED SARSA target = r + gamma * sum_a' pi(a'|s') Q(s',a')  -- exact expectation, still on-policy,
               lower variance than sampled SARSA; setting pi=greedy collapses it to Q-learning exactly
CONVERGENCE    Q-learning -> Q* w.p.1 (Watkins & Dayan 1992) IF every (s,a) visited infinitely often
               -- easy to silently violate with insufficient/poorly-scheduled exploration
DEEP RL        Q-learning + fn approx + replay = deadly triad (all 3 legs) -> needs DQN's target
               network stabilization; "deep SARSA" rare in practice -- on-policy can't replay freely
```
