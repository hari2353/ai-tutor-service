# Synthetic Data Generation: LLM-Generated Training Data, Augmentation, and Quality

> **Track:** T03 Classical ML · **Time:** 2h · **Prereqs:** `T03-classical-ml`, `T05-llm-internals` · **Updated:** 2026-10-31
> **Module id:** `T03-synthetic-data` · **Tags:** data, training, advanced

## The 30-second version

Synthetic data is training data generated by an AI model (usually an LLM) instead of collected from humans. The appeal: infinite data, no labeling cost, privacy-preserving (no real PII). The reality: synthetic data is only as good as the generator, and models trained on synthetic data inherit and amplify the generator's biases. The techniques: (1) **Self-Instruct** (generate instructions + responses from seed examples), (2) **Evol-Instruct** (evolve instructions to increase complexity), (3) **Magpie** (extract instruction-response pairs from a model's internal generation), (4) **data augmentation** (paraphrase, back-translation, noise injection), (5) **distillation** (train a small model on a large model's outputs). The 2026 reality: synthetic data is used in production (Phi-3, Gemma, Llama 3 were all trained on synthetic data). The key insight: synthetic data is not a replacement for real data — it's a complement. The quality ceiling is the generator's quality, and models trained purely on synthetic data degrade (model collapse). The best results come from mixing synthetic + real data.

## Why this gets asked

Because synthetic data is the most hyped data technique of 2024-2026, and interviewers want to know if you understand its limits. They probe: "would you train a model entirely on synthetic data?" (wrong answer: "yes, it's free and unlimited"; right answer: "no — model collapse, bias amplification, and quality ceiling. Use synthetic data to augment real data, not replace it"). Also probed: "how do you ensure synthetic data quality?" (answer: diversity metrics, deduplication, quality filtering with a separate model, human spot-checking). The principal-level probe: "your team needs 100k labeled examples for a niche task — design the data pipeline" (answer: seed examples → Self-Instruct/Evol-Instruct → quality filter → dedup → human spot-check → mix with real data).

## Lineage: past → present → future

**What came before.** Data augmentation (2010s): paraphrase, back-translation, noise injection for NLP; cropping, flipping, color jitter for vision. The pain: augmentation creates variations but not new information. Self-Instruct (2023, Wang et al.) was the breakthrough: use an LLM to generate new instruction-response pairs from seed examples, creating genuinely new training data. Alpaca (Stanford, 2023) used Self-Instruct to create 52k examples for $600, proving the concept.

**Where it stands now.** Synthetic data is standard: (1) **Self-Instruct** — generate instructions from seed examples, generate responses, filter by quality. (2) **Evol-Instruct** (WizardLM) — evolve instructions to increase complexity (depth, breadth, constraints). (3) **Magpie** (2024) — extract instruction-response pairs from a model's internal generation without explicit prompting. (4) **Distillation** — train a small model on a large model's outputs (Phi-3, Gemma). (5) **RLAIF** — use AI feedback to generate preference labels. The 2026 reality: synthetic data is used in production (Phi-3, Gemma, Llama 3 all used synthetic data). The live disagreement: how much synthetic vs. real data, and whether model collapse is inevitable (Shumailov et al., 2024) or avoidable with careful mixing.

**Where it's heading.** High confidence: synthetic data becomes standard for instruction tuning and preference learning. Medium confidence: quality filtering and diversity metrics become the bottleneck (not generation volume). Speculative: fully synthetic training pipelines (no real data) become viable for narrow domains, but for general-purpose models, real data remains essential.

## Mental model

```
SYNTHETIC DATA PIPELINE:
  Seed examples (50-100 human-written)
       │
       ▼
  Self-Instruct / Evol-Instruct (LLM generates new instruction-response pairs)
       │
       ▼
  Quality filter (separate model scores each example: relevance, correctness, diversity)
       │
       ▼
  Dedup (MinHash / semantic dedup to remove near-duplicates)
       │
       ▼
  Human spot-check (sample 1-5% for manual review)
       │
       ▼
  Mix with real data (typically 50-80% synthetic, 20-50% real)
       │
       ▼
  Train model

MODEL COLLAPSE (the risk):
  Model trained on synthetic data → generates synthetic data → trains next model
  → distribution narrows → diversity drops → quality degrades
  Fix: mix with real data, use diverse generators, monitor diversity metrics
```

## Recognition heuristics

- **"Generate training data for a niche task"** → Self-Instruct (seed examples → LLM generates more) + quality filter + dedup + human spot-check.
- **"Increase instruction complexity"** → Evol-Instruct (depth: add constraints; breadth: new topics; mutation: rephrase).
- **"Train a small model cheaply"** → distillation (large model generates outputs → small model trains on them).
- **"How do you prevent model collapse?"** → mix synthetic + real data, monitor diversity metrics, use diverse generators, human spot-checks.

## Common bugs and how these get shipped wrong

- **Training purely on synthetic data.** Model collapse: the model's output distribution narrows, diversity drops, quality degrades over generations. Fix: always mix with real data (at least 20-30%).
- **Not filtering quality.** Synthetic data contains hallucinations, errors, and low-quality examples. Fix: use a separate model to score each example; filter below threshold.
- **Not deduplicating.** LLMs generate similar examples repeatedly. Fix: MinHash or semantic dedup before training.
- **Not checking diversity.** Synthetic data tends to cluster around the seed examples' topics. Fix: measure topic diversity and add seeds for underrepresented areas.
- **Ignoring bias amplification.** The generator's biases (gender, race, cultural) are amplified in synthetic data. Fix: audit synthetic data for bias; use diverse generators.

## Interview questions

1. **"How would you generate training data for a niche task with no labeled examples?"** Answer: Self-Instruct — write 50-100 seed examples, use an LLM to generate new instruction-response pairs, filter by quality (separate model), dedup, human spot-check 1-5%, mix with any available real data. Cost: ~$100-500 for 10k examples.
2. **"What is model collapse and how do you prevent it?"** Answer: model collapse is the degradation of model quality when trained on synthetic data from previous models, due to distribution narrowing. Prevention: mix synthetic + real data (at least 20-30% real), use diverse generators, monitor diversity metrics, human spot-checks.
3. **"Self-Instruct vs Evol-Instruct vs Magpie?"** Answer: Self-Instruct generates new examples from seeds. Evol-Instruct increases complexity (depth/breadth/mutation). Magpie extracts instruction-response pairs from a model's internal generation without explicit prompting. Use Self-Instruct for basic augmentation, Evol-Instruct for complex tasks, Magpie for large-scale generation.

## Red flags that fail you

- "Synthetic data can replace real data" — model collapse, bias amplification.
- "Just generate 1M examples and train" — without quality filtering, dedup, and diversity checks.
- Not knowing the privacy-utility tradeoff of synthetic data (synthetic data is not private by default — it can leak training data).
- Confusing data augmentation (variations) with synthetic data (new information).

## Cheat card

- Self-Instruct: seed examples → LLM generates more → quality filter → dedup → spot-check.
- Evol-Instruct: depth (add constraints), breadth (new topics), mutation (rephrase).
- Magpie: extract instruction-response pairs from model internals (no prompting).
- Model collapse: train on synthetic → distribution narrows → quality degrades. Fix: mix with real data.
- Quality filter: separate model scores each example. Dedup: MinHash / semantic.
- Privacy: synthetic data is NOT private by default — can leak training data.
