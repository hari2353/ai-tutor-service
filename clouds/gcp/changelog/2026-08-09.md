## New / GA
- **Policy Troubleshooter MCP server (GA)** — Remote MCP server letting agents and AI apps troubleshoot IAM allow/deny decisions programmatically. ([src](https://docs.cloud.google.com/release-notes))
  - *Interview angle:* "How would an AI agent debug 'why did this IAM call get denied' without a human reading the audit log?" — there's now a first-party MCP server for exactly that.
- **Gemini Enterprise: Custom MCP server data stores (GA)** — Connect a custom MCP server to Gemini Enterprise for private data/tools; it calls the server's `tools/list` directly instead of requiring hand-written tool descriptions (a UX simplification landed 2026-08-06). ([src](https://docs.cloud.google.com/release-notes))
  - *Interview angle:* Good concrete example of MCP tool-discovery (`tools/list`) driving routing without manual metadata — ties directly into the MCP 2026-07-28 spec's emphasis on deterministic tool ordering.
- **VPC Service Controls service patterns (GA)** — Explicit per-API allow-listing (supported and unsupported APIs) for the private VIP and Private Service Connect `all-apis` bundle inside a perimeter. ([src](https://docs.cloud.google.com/release-notes))
  - *Interview angle:* "How do you allow a specific unsupported API through a VPC-SC perimeter without opening everything?" — service patterns are the new lever.
- **Cloud Monitoring Telemetry API for OTLP metrics (GA)** — Ingest OTLP metrics into Cloud Monitoring via an OpenTelemetry Collector/OTLP exporter, no proprietary agent required. ([src](https://docs.cloud.google.com/release-notes))
  - *Interview angle:* "How do you get OTel metrics into Cloud Monitoring?" — direct OTLP ingestion is now GA, not just via a GCP-specific exporter.
- **GKE TPU Subslicing (GA)** — Dynamic sub-/super-slicing for Ironwood (TPU7x): incrementally provision node pools into smaller topologies instead of committing to a full cube/litepod. ([src](https://docs.cloud.google.com/release-notes))
  - *Interview angle:* "How do you right-size a TPU node pool for a workload smaller than a full pod?" — dynamic subslicing is now GA.
- **GKE Autopilot Arm ComputeClasses (GA)** — `autopilot-arm` / `autopilot-arm-spot` general-purpose Arm compute classes on Standard and Autopilot clusters. ([src](https://docs.cloud.google.com/release-notes))
  - *Interview angle:* Arm workloads on GKE Autopilot no longer require Standard-mode workarounds.
- **Vector Search 2.0 (GA)** *(gap-window item, WebSearch-sourced)* — Repositioned as the retrieval/knowledge-core engine for AI applications under Gemini Enterprise Agent Platform. ([src](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/release-notes)) — accessed 2026-08-09
  - *Interview angle:* "What does GCP use for vector retrieval in an agent stack now?" — Vector Search 2.0 is the current GA answer, positioned as core infra, not an add-on.

## Changed limits & behaviour
- **AlloyDB for PostgreSQL — BigQuery sync (preview)** — One-time or scheduled table sync from BigQuery into AlloyDB, plus lakehouse-style federated access, narrowing the operational/analytical gap without a separate ETL pipeline. ([src](https://docs.cloud.google.com/release-notes))
  - *Interview angle:* "How do you serve BigQuery data with low-latency transactional access?" — AlloyDB↔BigQuery sync is a new direct answer, not "build a CDC pipeline."
- **Cloud SQL (MySQL/PostgreSQL/SQL Server) DNS automation (GA)** — Automatic per-instance DNS record management for Private-Service-Connect-enabled instances, including an optional global write-endpoint DNS that follows the current primary. ([src](https://docs.cloud.google.com/release-notes))
  - *Interview angle:* "How does a client find the current Cloud SQL primary after failover without app-side reconfiguration?" — global write-endpoint DNS auto-follows the primary now.
- **AlloyDB BM25 full-text indexes (preview)** — `pg_textsearch` extension adds BM25 indexes (PostgreSQL 17/18) alongside existing vector search — hybrid lexical+semantic retrieval in one engine. ([src](https://docs.cloud.google.com/release-notes))
  - *Interview angle:* "How do you do hybrid search (keyword + vector) in AlloyDB without bolting on Elasticsearch?" — BM25 indexes are now native.
- **Vertex AI documentation frozen** *(gap-window item, WebSearch-sourced)* — Vertex AI's release-notes page is no longer updated; Google directs all new AI-platform documentation to Gemini Enterprise Agent Platform. Treat "Vertex AI" as the legacy brand name for the same underlying service going forward. ([src](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/release-notes)) — accessed 2026-08-09
  - *Interview angle:* If a candidate (or the tutor) says "Vertex AI" in 2026, expect the interviewer to have Gemini Enterprise Agent Platform branding in mind — know both names refer to the same platform.
